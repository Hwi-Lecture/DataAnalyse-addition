# 대시보드 실습: Ames 주택 가격 대시보드 만들기

앞에서 노트북으로 확인한 내용(데이터 탐색, 가격 예측, 정보 추가 실험)을 **Streamlit 대시보드 화면**으로 만듭니다.
이번 실습에서는 코드를 직접 쓰지 않고, **OpenCode에게 요청해서** 만듭니다.

## 진행 방식

각 단계는 아래 순서로 진행합니다.

1. **요청하기**: 단계의 프롬프트를 OpenCode에 입력합니다. 그대로 입력해도 되고, 내 말로 바꿔도 됩니다.
2. **실행하기**: 화면을 확인합니다. 수정 후에는 브라우저에서 `Rerun`을 누르거나 새로고침합니다.
3. **확인하기**: "확인할 것"을 보고 결과가 맞는지 봅니다.
4. **기록하기**: 확인한 내용을 한 줄로 적습니다.

## 사전 정보

| 항목 | 내용 |
|---|---|
| 데이터 | `data/AmesHousing.txt` (미국 Ames시 주택 거래 2,930건, 2006~2010년) |
| 맞히려는 값 | 거래 가격 `SalePrice` (달러) |
| 실행 명령어 | `streamlit run app.py` |

## 진행 중 유의할 점

- 한 번에 한 가지만 요청합니다. 여러 가지를 한꺼번에 요청하면 어디서 문제가 생겼는지 알기 어렵습니다.
- 단계가 끝날 때마다 `app.py`를 복사해 `app_step1.py`, `app_step2.py`처럼 저장해 둡니다. 화면이 깨졌을 때 돌아갈 수 있습니다.
- 화면이 이상하면 오류 메시지를 복사해서 OpenCode에 그대로 붙여넣고 "이 오류를 고쳐줘"라고 요청합니다.
- 숫자가 이상하면 "이 숫자는 어떻게 계산한 거야?"라고 되묻습니다.

## 0단계. 데이터와 목표 알려주기

코드를 쓰기 전에 AI가 데이터를 제대로 이해했는지 확인합니다.

```
이 폴더의 data/AmesHousing.txt는 미국 Ames시의 주택 거래 데이터야 (탭으로 구분된 파일).
나는 이 데이터로 Streamlit 대시보드를 만들 거야.
대시보드에는 (1) 데이터 탐색 결과 몇 개와 (2) 집 값 예측 화면을 넣을 거야.

아직 코드는 쓰지 마. 먼저 아래만 해줘.
1. 데이터가 몇 행, 몇 열인지 알려줘.
2. 가격(SalePrice)과 관련 있을 것 같은 열 12개를 골라서 한국어 뜻과 함께 표로 보여줘.
3. 빈 값이 있는 열이 있는지 알려줘.
코딩을 모르는 사람도 이해할 수 있게 쉬운 한국어로 설명해줘.
```

**확인할 것**
- 행 2,930개, 열 82개로 답했는가
- AI가 고른 12개 중 내가 보기에 이상한 항목이 있는가

| 기록 | 내용 |

| AI가 고른 12개 중 눈에 띈 항목 | |

## 3단계. 데이터 탐색 ② 가설 세우고 그래프로 확인

먼저 가설을 한 줄 적고 시작합니다.

> 가설: 가격은 ______ 와 관련이 클 것 같다.

```
app.py에 "가설 확인" 구역을 추가해줘.
1. 선택 상자로 항목(Gr Liv Area, Overall Qual, Year Built, Garage Area)을 고르면 그 항목과 가격의 관계를 산점도로 보여줘.
   (점이 너무 많으니 투명도를 주고, 추세선도 하나 그려줘)
2. 동네(Neighborhood)별 평균 가격을 높은 순으로 막대그래프로 보여줘.
3. 각 그래프 아래에 그래프에서 읽을 수 있는 내용을 한 줄씩 써줘.
```

**확인할 것**
- 선택 상자에서 항목을 바꾸면 그래프가 바뀌는가
- 내가 세운 가설과 그래프가 맞는가
- 동네에 따라 평균 가격이 얼마나 다른가

| 기록 | 내용 |

| 내 가설 | |
| 가설이 맞았나, 달랐나 | |
| 평균 가격이 가장 높은 동네 / 낮은 동네 | |

## 4단계. 집 값 예측 화면

```
app.py에 "집 값 예측" 구역을 추가해줘.
- 사용할 12개 정보: Gr Liv Area, Lot Area, Overall Qual, Overall Cond, Year Built, Year Remod/Add, Total Bsmt SF, Garage Area, Garage Cars, TotRms AbvGrd, Full Bath, Yr Sold
- 빈 값은 각 열의 중앙값으로 채워줘.
- 선형회귀 모델을 80:20으로 나눠서 학습시키고(random_state=42), 모델은 한 번만 학습하도록 캐시해줘.
- 왼쪽 사이드바에 12개 정보를 슬라이더나 숫자 입력으로 만들어줘. 기본값은 각 열의 중앙값, 범위는 데이터의 최솟값~최댓값.
- 화면에는 "예상 가격: $000,000"을 크게 보여줘.
- 예측값이 0보다 작게 나오면 0으로 보여주고 안내 문구를 띄워줘.
```

**확인할 것**
- 슬라이더를 움직이면 예상 가격이 바뀌는가
- 면적(Gr Liv Area)과 품질(Overall Qual)을 올리면 가격이 오르는가
- 극단적인 값(면적 5,000 등)을 넣으면 예측이 자연스러운가

| 기록 | 내용 |
|---|---|
| 기본값(중앙값)일 때 예상 가격 | |
| 면적을 올렸을 때 변화 | |
| 이상하게 느껴진 예측 | |

## 5단계. 동네 정보를 추가해서 비교하기

3단계에서 동네별 가격 차이가 크다는 것을 봤습니다. 지금 예측 모델은 동네를 모릅니다.

> 가설: 동네 정보를 추가하면 가격을 더 잘 맞출 것이다.

```
예측 모델에 동네(Neighborhood)를 추가해서 비교해보고 싶어.
1. 동네를 넣지 않은 모델과 넣은 모델, 두 개를 같은 훈련/평가 데이터로 학습해줘.
2. 평가용 데이터에서 두 모델의 MAE(평균 오차 달러)를 계산해서 "동네 없음 → 동네 있음"으로 나란히 보여줘.
3. 사이드바에 동네 선택 상자를 추가하고, 예측 화면에는 두 모델의 예상 가격을 나란히 보여줘.
기존 코드는 최대한 유지하고 필요한 부분만 고쳐줘.
```

**확인할 것**
- MAE가 줄었는가
- 동네를 바꾸면 "동네 있음" 예측만 바뀌는가
- NridgHt 같은 비싼 동네와 저렴한 동네에서 예측 차이가 얼마나 나는가

| 기록 | 내용 |
|---|---|
| MAE 동네 없음 → 동네 있음 | |
| 동네를 바꿨을 때 예측 변화 | |
| 가설과 같았나, 달랐나 | |
